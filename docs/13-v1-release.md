# PolyYaps V1.0 — Complete 30-Day Webapp

## Scope

V1.0 completes the first end-to-end PolyYaps product: a mobile-first European Portuguese learning PWA with a 30-day curriculum, adaptive review, practical checkpoints, speaking practice, gamification, local backup and offline support.

## V0.6 — Speaking and listening

Added:

- centralized `pt-PT` speech playback;
- browser speech-recognition detection;
- one-shot Portuguese transcription when the browser supports it;
- local text similarity scoring using character distance + word overlap;
- speaking feedback inside normal lessons;
- microphone answering inside later scenario challenges;
- graceful self-assessment fallback when speech recognition is unavailable.

Speaking is progressive enhancement rather than a hard dependency. This is deliberate so the course remains usable on iPhone/browser combinations where speech-recognition support differs.

## V0.7 — PWA and offline

Added:

- Web App Manifest;
- PolyYaps app icon;
- standalone/mobile metadata;
- deployment-path-independent Vite build;
- service worker;
- app-shell precaching;
- runtime caching of same-origin assets;
- cached navigation fallback after initial online load.

The app can therefore be installed/added to the Home Screen and can reopen its cached application shell without network after it has been loaded online successfully.

## Data model

### Course progress

Stored in localStorage:

- current day
- XP
- streak / longest streak
- streak freezes
- completed days
- lesson/challenge results
- learned item keys
- passport stamps
- achievements
- final course completion date

### Mastery

Stored in IndexedDB per item:

- mastery level 0–4
- strength 0–100
- seen/correct/wrong counts
- last evidence type
- last review
- next review
- speaking/spontaneous-use counters
- weakness category

## Backup

The Settings screen exports both storage layers into one versioned JSON file and can restore that file later. Reset clears both course progress and item mastery.

## QA

A temporary QA pull request was used to expose GitHub Actions results for the final codebase.

The first run found configuration/type issues in the prototype-era setup:

- `allowImportingTsExtensions` in the Node TypeScript config;
- the temporary React type shim causing implicit event `any`s;
- missing Vite CSS side-effect declarations;
- npm caching configured without a lockfile.

These were replaced/fixed with:

- standard `@types/react` and `@types/react-dom`;
- `vite/client` declarations;
- cleaned `tsconfig.node.json`;
- cache-free npm setup while the repo has no lockfile.

The follow-up `Build PolyYaps` and `PolyYaps CI` jobs both completed successfully through dependency install and `npm run build` (`tsc -b && vite build`).

## Known limitations

1. Browser `SpeechRecognition` availability and behavior varies. PolyYaps falls back to guided self-assessment.
2. Audio is currently generated by the device/browser pt-PT speech synthesizer rather than professionally recorded native-speaker audio.
3. Progress is local-first rather than synced through a user account.
4. The service worker provides an offline app shell and runtime asset cache; no remote speech service is cached or required.
5. GitHub Pages deployment is configured, but repository Pages settings/permissions may still need to permit the workflow before a public URL becomes active.
